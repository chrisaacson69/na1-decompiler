# `source/` — the recovered game source, as a pipeline ladder

> The "see the whole picture" payoff. Nobunaga's Ambition reconstructed from the
> ROM at every level of abstraction, each decompiler stage in its own folder so you
> can walk ROM → readable C. Generated **once**, committed, read like source — never
> re-derived per session (the anti-drift thesis applied to the project's most valuable
> output).

## The four stages

| Dir | Stage | What it holds |
|---|---|---|
| `1-asm-6502/` | native disassembly | `bank_NN.asm`: every bank force-decoded to 6502 (`disasm6502.py`), the rawest view; the bytecode banks decode as 6502 garbage, which is the point. **`bank_NN_labeled.asm` is the one to read** for the six code banks (0/1/2/10/14/15), laid out like the VM listing: names and branch targets flush left, instructions indented as `ADDR: bytes  mnemonic operand`. Native code comes from the discover walk (bank 15: the instruction starts `tools/native_discover.py` proves against the traces); each bytecode sub is its name, its `jsr vm_entry` and frame word, and one line pointing at `2-asm-vm/bank_NN_vm_labeled.asm`; the rest is data rows with an ASCII gutter. Regenerate with `py -3.14 tools/mesen-labels.py --asm` (generated by `tools/labeled_6502.py`); `--verify` checks they are current. Plus the full-ROM `.asm` header and `chr_rom.bin`. |
| `2-asm-vm/` | VM bytecode | The Sea-16 VM bytecode of the code banks (the interpreted layer the game logic actually runs in), two layouts of one walk. **`bank_NN_vm_labeled.asm` is the one to read**, laid out like Mappy's labeled listing: each routine's name and the `L_XXXX:` branch targets flush left (in-routine jumps name their label), and every instruction indented under them as `ADDR: bytes  mnemonic operand`, so a C line's `// $XXXX` greps straight to it. `bank_NN_vm.asm` is the decompiler's input (`vm_decompile.parse_listing` and several `tools/` read its address-led lines); don't hand-edit or reformat it. |
| `3-c-basic/` | basic decompile | `bank_NN.raw.c` — bytecode → **direct goto/label C, no structuring**. The intermediary the structure engine folds, AND the **CFG-equivalence witness** the gate proves `4-c/bank_NN.c` equivalent to. |
| `4-c/` | structured C (canonical) | `bank_NN.c` — the readable C (`if`/`while`/`switch`/`do-while`), structured by **DREAM** (owns 471 of 495; the **V2** reducer is the per-sub fallback for 19, and 5 are formula overrides). **This is what you read.** |

`3-c-basic/` and `4-c/` also hold the merged PRG-keyed `all_banks*.c`. Open a `3-c-basic`/`4-c` pair side by side to *see* what the structure engine did.

**The bytecode surface is the whole engine:** banks 0/1/2/15 = 495 functions, ~11.8k lines of C (bank 1 = the economy engine, bank 2 = combat+map, bank 15 = kernel-side). Banks 03–14 are data (0 bytecode subs).

## How it's made

Everything here is generated by the shared engine, emu-harness (`emu_harness.vm.koei.nes`). The 2-4 tiers
regenerate with one command, from any directory, with NA1's ROM in the machine's ROM store (emu-harness `config.toml` `roms`; resolved through the `[na1]` profile, SHA-1 checked):

```
py -3.14 tools/na1_regen.py      # banks 0, 1, 2, 10, 14, 15: both VM listings, 4-c (DREAM), 3-c-basic (--raw)
```

That runs `emu_harness.vm.koei.nes.titles` per bank: `disasm na1 <bank> <out>` (the decompiler input),
`disasm ... --labeled` (the reading view), `decompile` (DREAM primary, V2 fallback) and `decompile --raw`, then
adds each C file's banner. **Deterministic:** the fixed ROM plus `../mesen-labels.toml` (and
`../asset-enums.toml`) give byte-identical output, so these are committed and only regenerated when the engine or
the registry changes. `3-c-basic` and `4-c` differ only by structuring, so a side-by-side shows exactly what
DREAM folded; emu-harness `gates.cfg_gate --dream` proves the pair equivalent per sub. Registry edits go
through the guarded apply tools (rename-only diffs), never by hand into `source/`.

## Reading the C — caveats

- **`// TODO:` lines (~22%)** are opcodes the decompiler has a byte-length for but no semantic translation yet. The surrounding structure (control flow, handled ops, frame slots, host-calls) still carries the logic. TODO density drops as opcodes get decoded.
- **`/*stack underflow*/ regA`, `/* via argN */`** — the decompiler's heuristic for implicit args passed via frame-shadow writes (see the `math32_3arg` label comment about reading uninitialized stack). Not a bug in the C; a marker of an inferred value.
- **`local10 = (x / 0)`** and similar — artifacts of the same uninitialized-arg heuristic; cross-check against the emulator (`nobunaga_vm.py`) for ground truth, which is how every *verified* formula here was confirmed.
- Field accesses like `arg1->output` use NA1's province-record field map — now selected per-title by
  `vm_decompile.set_schema("na1")` (the shared engine serves NA1/NA2/ROTK/GK, each with its own layout;
  NA1's is the SRAM-verified one in `../docs/07-sram-save-layer.md`).

**Ground-truth rule:** the C is the map; the emulator is the territory. Every formula cited as "verified" in memory/chapters was validated by executing the handler in `nobunaga_vm.py`, not by reading this C alone.
